The folder, package, executable and configuration directory use `lofiji`.

All bundled backgrounds use PNG/GIF assets. Native city/interior geometry and old previews were removed. CC0 third-party art/audio and generated artwork are attributed alongside their files. A static rainy-window PNG is intentionally retained for custom wallpaper use.

The clock, images and ambient files need no runtime internet. Ambient playback needs optional mpv; streamed YouTube additionally needs yt-dlp and Node.js and remains subject to source availability. PNG/GIF display uses half-block cells rather than a terminal graphics protocol. GIF rendering caps at 10 fps and custom decoded animations are limited to 64 MiB/512 frames. Built-in PNGs use localized rendering effects; custom PNGs remain static. No audible listening comparison was performed in this verification pass.

Desktop notifications still depend on notify-send and the desktop notification service and have not been tested end to end. Timer sessions do not persist across restarts; Linux monotonic time excludes system sleep. SIGKILL cannot run terminal/process/temp-file cleanup.

The installer places the executable in `~/.local/bin/lofiji`. The managed i3 include under the user configuration directory launches Kitty at login. No duplicate desktop autostart entry is created. The original i3 config was backed up to `config.before-lofiji`; startup can be disabled with the installer.

The UX revision was checked in terminal sessions at 60×17, 80×24 and 120×36. Compact chat and lists keep a live clock header. The checks cover Help scrolling, section navigation, explicit Settings save, chat draft and history retention, a fresh conversation, and reply cancellation.

AI is off by default. Optional providers use native APIs through a cancellable curl worker, with editable models/endpoints and provider-specific settings remembered across switches. Credentials are read from the selected environment variable only when requested. Cloud requests send active goals/tasks and recent conversation to the configured endpoint; model replies cannot modify saved records. Live provider authentication and account-specific model availability were not tested. Goal files are created only when users save an entry; planning snapshots use in-memory examples and never make network requests. Conversation and AI suggestions are transient; goals/tasks persist.
